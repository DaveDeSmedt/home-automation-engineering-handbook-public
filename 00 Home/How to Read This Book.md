# How to Read This Book

This is both a book and an Obsidian vault. Read it linearly if you are learning the ideas, or follow links when you are designing one feature.

## The recommended first pass

1. Read [Preface](Preface.md), [Engineering Principles](Engineering%20Principles.md) and [System Overview](../01%20Architecture/System%20Overview.md).
2. Read [Stateful Automation Architecture](../01%20Architecture/Stateful%20Automation%20Architecture.md) before building a complex flow.
3. Choose one service: [Lighting](../03%20Systems/Lighting/Lighting.md), [Presence Detection](../03%20Systems/Presence/Presence%20Detection.md), [Audio](../03%20Systems/Audio/Audio.md) or [Energy Management](../03%20Systems/Energy/Energy%20Management.md).
4. Build one small automation using [Advanced Flows](../05%20Homey/Advanced%20Flows/Advanced%20Flows.md) and test it with [Verification Standards](../06%20Standards/Verification%20Standards.md).
5. Use [Maintenance](../07%20Operations/Maintenance.md) and [Troubleshooting](../07%20Operations/Troubleshooting.md) as the system grows.

## How examples work

Every worked example has a label. Do not copy a **proposed** flow directly into a live system. Translate the intent, confirm the relevant Homey cards and integration behaviour, then test the smallest safe version.

## Links and diagrams

Obsidian opens `Obsidian-style links` and renders Mermaid diagrams. In a plain Markdown viewer, use the file tree or the links in [README](../README.md). Diagrams describe logic, not electrical wiring or physical security layouts.
